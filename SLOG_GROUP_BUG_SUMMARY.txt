SLOG GROUP BUG - COMPLETE ANALYSIS & REPRODUCTION
================================================================================

PROJECT: disapyr-link
FILE: internal/logger/db_handler.go
ISSUE: DBHandler cannot properly handle slog.Group() attributes

================================================================================
PROBLEM
================================================================================

When you call:
  logger.Info("test", slog.Group("g", "k", "v"))

Expected output:
  {"g.k": "v"}  OR  {"g": {"k": "v"}}

Actual output:
  {"g": [{"Key":"k", "Value":{}}]}  ← WRONG! Raw slog.Attr structs

ROOT CAUSE:
  In DBHandler.Handle() lines 68 and 73, the code calls a.Value.Any() on all
  attributes without checking if they're Groups. When a is a Group, Any() 
  returns []slog.Attr, which is stored directly in the map and later 
  json.Marshal() serializes it as a Go struct with "Key" and "Value" fields.

================================================================================
THE FIX
================================================================================

Method: DBHandler.Handle() in internal/logger/db_handler.go

Changes:
  1. Add a recursive helper function to process attributes
  2. Check if attribute is a Group: a.Value.Kind() == slog.KindGroup
  3. If yes, recursively process its attributes with updated key prefix
  4. If no, store the value as before

Key code pattern:
  var processAttrs func([]slog.Attr, string)
  processAttrs = func(attrList []slog.Attr, prefix string) {
    for _, a := range attrList {
      key := attrKey(prefix, a.Key)
      if a.Value.Kind() == slog.KindGroup {
        groupAttrs := a.Value.Group()
        processAttrs(groupAttrs, key)
      } else {
        attrs[key] = a.Value.Any()
      }
    }
  }

Benefits:
  ✓ Properly handles slog.Group() attributes
  ✓ Supports nested groups
  ✓ Maintains dot-notation flattening
  ✓ Fully backward compatible
  ✓ Minimal performance impact
